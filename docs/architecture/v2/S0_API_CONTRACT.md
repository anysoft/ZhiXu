## 2. 认证与授权：当前证据和 v2 强制边界

[Express](../../../back/loaders/express.ts#L39) 先配置大小写/strict routing、base URL rewrite、Backup admission 与独立 Webhook；再配置 parsers、JWT、Panel/App token 校验，最后 `/open/* → /api/*`。JWT 只采用 HS384；[isValidToken](../../../back/shared/auth.ts#L18) 同时校验签名、exp 及 AuthInfo 对应平台 token 列表。仅持有签名正确 JWT 或客户端声称“Panel”都不足以授权。

[AppScope](../../../back/data/open.ts#L27) 的 TypeScript union 不含 subscriptions/workspaces，但 [Open API](../../../back/api/open.ts#L29) 接受任意字符串 scope；Express 运行时只检查数组 includes。因此“没有类型定义”绝不等于拒绝访问。当前部分 controller 用 originalUrl 正则拒绝/open（[Workspace wrapper](../../../back/api/codeWorkspace.ts#L34)、[Tasks](../../../back/api/tasks.ts#L28)）；有 base URL 时不能仅凭一个开头正则判定最终来源。

**v2 强制要求**：所有新 Workspace、文件、Git、Sync、Discovery、继承及 Task 管理路由先执行显式 `requirePanelSession` 语义：

1. 从 Authorization Bearer 取 token，按当前 HS384 和平台 membership 验证会话；不接受 query、cookie、App token、Webhook secret 替代 Panel session。当前 getToken 支持 desktop-/mobile-前缀的既有 transport 规范可继续使用，但结果必须重新验证会话，见[getToken](../../../back/config/util.ts#L48)。
2. 在 rewrite 前后保持可信来源/principal 分类；原始 namespace 为/open 时一律 403 PANEL_SESSION_REQUIRED，即便 App 声明 workspaces/system 等 scope、同名 token 或路由已改写。不能依据用户可伪造的请求 header 决定 principal。
3. 已验证 Panel 会话拥有当前单账户平台的管理权限；本轮不虚构现有多租户 RBAC。Git Push 另验 Repository 默认 Credential 的 WRITE capability 及显式远端 branch；无 force、任意 remote/refspec 或私有 branch 外泄。
4. 缺失/失效 Panel token 为 401 AUTHENTICATION_REQUIRED；有效非 Panel 身份为 403 PANEL_SESSION_REQUIRED。未经授权时不泄露资源存在性/Task 引用/代码内容。
5. [protectApiMutations](../../../back/services/backup/apiLifetime.ts#L4) 只持有平台备份 mutation admission 至 handler 真正结束，**不是鉴权或 CSRF 替代品**；socket close 不应释放仍在执行的写入租约。全局 CORS/隐藏按钮不授予权限。
6. Webhook 继续独立[POST /hooks/:publicId](../../../back/api/triggerWebhook.ts#L7)：secret 认证、64KiB、禁 query、Idempotency-Key；只可产生 Task 触发事件，不能访问 Workspace/文件/Git/同步/Discovery。内部 scheduler 直接调用 domain service，不经/open 或 HTTP 复用用户 token。

认证顺序、错误净化和类型/生命周期校验必须在任何源码读取、目录分配、SQL 副作用或 Git 调用之前完成。错误路径同样受平台 admission；新 namespace 的 parser/validation 错误须在现有可能返回 Sequelize 原文的通用 handler 前被安全映射。本轮只静态验证了这些现有路径，未运行 API 鉴权测试。

## 3. 统一响应、参数和失败规则

成功沿用现有资源 API envelope：同步完成 `HTTP200 {code:200,data}`；异步已受理 `HTTP202 {code:202,data}`。列表新 Workspace 采用 `{items,page,size,total}`，page 默认 1、size 默认 50 且最大 200；既有未改列表维持当前分页 DTO，不为统一而修改保留域。无数据删除成功为 `data:null`。错误为 `{code:HTTP_STATUS,error_code,message,retryable,resource?,operation?,details?}`，其中 message 来自固定安全注册表，不是异常文本。

所有 ID 为正 safe integer，**WorkspaceOperation ID 和 Backup/Snapshot ID 为 UUID 字符串**。时间戳 UTC ISO-8601；Sync INTERVAL 统一使用 interval_ms（整数毫秒）和 anchor_at（UTC ISO-8601），不另定义 interval_seconds 或 duration_ms 别名。git commit 使用规范完整 SHA。路径仅规范相对路径，不接受 local_path/root_key/rootIdentity 等客户端写入。public DTO 不返回 host 绝对路径、dev/ino、owner_token、journal_key、Git 私有 branch、Credential、Secret ENV 值。目录 CAS 用认证 opaque identity_token，不把 inode 作为公开路径授权。

实际注册顺序必须先静态子路径（例如`/hooks/reorder`、`/sync-history`、`/operations/:operationId`），再对应动态参数；strict/case-sensitive 路径规范与 base URL 统一校验，不能让数字 ID parser 吞掉静态子资源。候选 JSON 是路由合同，不是可直接按数组顺序注册的实现代码。

请求 schema 拒绝未知字段和非法联合组合：LOCAL 携带 git/ref/sync/discovery 字段、GIT 缺 Repository/ref，皆拒绝。metadata PATCH 只准 name；type、Repository、ref、root、source_generation 及 lifecycle 不可任意 PATCH。Git Tag/Commit 创建时固定解析 commit，scheduled sync 拒绝；源切换新建 Workspace 或另行显式 Task rebind。

Metadata CAS、文件 hash、租约和幂等分别处理不同问题：

| 范围                           | 精确控制                                                                            | 失败行为                                                                                    |
| ------------------------------ | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Workspace metadata / lifecycle | expected_version = Workspace.version                                                | 409 WORKSPACE_VERSION_CONFLICT；不改变 lifecycle                                            |
| SyncPolicy/DiscoveryPolicy     | expected_version = 子资源 version；未持久行时 0=create-if-absent                    | 409 WORKSPACE_VERSION_CONFLICT / DISCOVERY_VERSION_CONFLICT；老 job 按旧 version 作废       |
| Task/Profile 及其变量聚合      | owner expected_version；事务内验证并推进 aggregate version                          | Task 用 TASK_VERSION_CONFLICT；Profile 用 WORKSPACE_VERSION_CONFLICT，resource 指明 Profile |
| ConfigBinding/Hook             | 子资源 expected_version；Task definition/effective resources 一致性另由执行合同复核 | 保留 CONFIG_EDIT_CONFLICT；不盲重试                                                         |
| File save/delete               | expected_hash 与稳定 open/fstat 身份，操作全程 Workspace EX                         | 409 WORKSPACE_FILE_CONFLICT，浏览器保留 buffer                                              |
| Directory rename               | tree 返回的 expected_identity token；目的地 no-replace                              | 409 WORKSPACE_FILE_CONFLICT 或 WORKSPACE_DESTINATION_EXISTS                                 |

## 4. 幂等、创建及生命周期

Workspace create/lifecycle/recovery 和 manual Sync 必须带`Idempotency-Key`（1..200 可见 ASCII）。服务端保存 namespace、认证 actor、操作/资源、规范请求 hash 与结果身份；相同 key/相同请求在认证后、CAS 前返回原 operation/SyncRun，即便旧 expected_version 此时过期；相同 key 不同 body/target 返回 409 IDEMPOTENCY_KEY_CONFLICT。作用域 key 的持久化编码可为 SHA256，不保存 raw token；集合 CREATE 的 key 作用域是 actor+method+collection，在分配 Workspace ID 之前确定且跨 Workspace 唯一，不能把新分配 ID 加入 scope 导致重试创建第二份。WorkspaceOperations.request_key、WorkspaceSyncRuns.request_key 和 TaskRuns.submission_key 是对应持久 owner，不能仅内存去重。retention 至少覆盖对应 operation/Run 可重放期，未完成操作不得释放 key。

File PUT、create、rename 和变量/配置等已有 CAS 操作不强行新增另一套 API request queue：重复失联后重读当前结果/hash，create 保持 no-clobber。手动 TaskRun 允许 Idempotency-Key，Panel UI 必须提供；内部事件固定 event identity，不生成随机新 key 重投。

创建统一返回 202，包含 CREATING Workspace 与 CREATE operation。LOCAL 成功后不运行 git init；GIT 成功必须有同 ID 有效扩展及独占 checkout；UI 轮询 operation/Workspace READY 才开放 Files/Task。

生命周期/storage 分开：CREATING/READY/ARCHIVED/DELETE_REQUESTED/TOMBSTONED/ERROR/RECOVERY_REQUIRED，与 PROVISIONING/PRESENT/RECLAIMING/RECLAIMED。ARCHIVED 可授权持 EX 读取源码和历史，禁止新 Task 绑定、Run、Sync 及普通写入。只允许显示名称修改、unarchive/delete、引用解除/Task 删除与必要默认解绑；ENV/Profile/Config/Runtime/policy 新增或编辑需先 unarchive。archive/unarchive 是显式 operations，不接受任意 PATCH state。归档先关 producer/admission 并 drain 已有 RESOLVING/RUNNING 及实际 owner；完成事务取消稳定 QUEUED Run/Sync 为 CANCELLED/WORKSPACE_ARCHIVED，同事务将 Tasks.enabled 与 SyncPolicy.enabled 设 false 并推进版本。Unarchive 校验后 READY，不恢复这些 flags、不创建新执行。候选 drain 期限 300000ms 到期若 active owner 仍在，operation 失败 WORKSPACE_BUSY 并恢复原 READY/admission，不能杀 child、提前 disable 或提前取消 queue；清理归属不明则 RECOVERY_REQUIRED，不报成功。

DELETE 仅接受 ARCHIVED、无任何 TaskSource/active Run/Sync/journal/owner 冲突、所有权可信、满足保全的资源；失败 409 保持原状态。非空 LOCAL 及所有 GIT 目录默认要求 validated READY backup 精确覆盖 generation/revision/inventory hash 并有 persistent preservation hold；empty LOCAL 可 null。请求 `{expected_version,confirm_reclaim:true,preservation_backup_id:UUID|null}` 无 force/skip_backup 字段。

受理 202 后进入 DELETE_REQUESTED，Operation 受控 quarantine 与 reclaim 完成后为 TOMBSTONED+RECLAIMED。历史 TaskRun/SyncRun 仍 FK→Workspace identity 且快照保留；**历史只阻 metadata purge，不阻源码目录回收**。DELETE 不级联删 Task；须先显式删/重绑 Task。最终 metadata purge 由内部 retention/GC 执行，所有 FK、保全和 backuphold 满足后才能做，不提供 UI force。恢复状态不明或 owner marker 不可信时保留目录，进入 RECOVERY_REQUIRED，绝不递归猜删。

## 5. Sync、Discovery 及执行可见性

SyncRun DTO 分别显示`git_update_status`、`discovery_status`、`event_status`和 before/target/actual commit。代码已应用但 Discovery 失败时明确返回 APPLIED/FAILED/NOT_COMMITTED，SyncRun=RECOVERY_REQUIRED，phase=APPLIED_PENDING_RECONCILIATION；不能显示单一 FAILED 暗示没有变更。MVP 采用保守 A，阻整个 Workspace 执行/文件内容访问与写入，只允许安全 metadata/status/recovery。修复由恢复 owner 核 HEAD 后幂等续作，成功事务同时提交对账、applied_commit、SyncRun SUCCESS 和 outbox，事务后才 dispatch。

首次成功 Sync 的 `initial=true` 单独表示建立 Workspace 更新基线：若 READY checkout 已经是目标 SHA，before/actual/after 可相同，git_update_status=UNCHANGED 仍可 SUCCESS + initial outbox；不能伪称 Git 移动或虚增 content_revision。完成事务提交 SUCCESS、initial outbox、GitWorkspace.baseline_established 的 write-once 0→1 以及 baseline_sync_run_id，缺少任一事实不得提交。baseline_sync_run_id 是可因历史 retention 清空的引用；判定是否首次必须看永久 baseline_established，不能因 pointer=NULL 再发初始事件。只有显式 GitUpdate 且 fire_on_initial=true 才运行，默认 false。后续相同 SHA 为 NO_CHANGE 且零新 outbox，新增/重启 Trigger 不回放旧 initial。SyncRun DTO 公开 initial 及三事实，UI 必须区分初始基线与内容移动。

公开 Discovery preview/apply 仅适用于 READY、同 source generation/revision/commit/policy/task/trigger 版本。preview_token 为小型 HMAC/opaque token，认证绑定 workspace_id/source_generation/content_revision/commit/policy_version/plan_hash/expiry/key_version 与已验证 Panel actor；TTL 候选 300000ms。plan_hash 来自排序、规范化的纯动作及 Task/Trigger 版本，不包含 Secret/host path 或依赖当前时刻的 next_fire_at。HMAC 使用系统安全 key 的独立用途密钥版本，绝不使用 Git 凭证。apply 在同租约下重新 scan/plan 并比较 digest，避免持久化另一种 Preview 业务实体或在 token 塞整张 Task 表；任一事实改变或过期均 DISCOVERY_PREVIEW_STALE，无 Task 写入。apply 不产生 Git 同步成功事实或新的 GitUpdate 事件；也不能绕开 pending Sync recovery 去“补一个普通 apply”。忽略项写 WorkspaceDiscoverySuppression，手动 Task 不受影响，删除 DISCOVERED Task 需与 suppression 同事务，保留 USER Cron 接管/tombstone。禁用 Discovery 不等于删除 Task 或解除未完成恢复屏障。

Task 创建的 Source 必为 WORKSPACE_ENTRYPOINT，CRUD 不要求 Repository；只允许同 Workspace Profile。Run POST 只接受 wait_mode，不接受替换 command/host path/workspace/runtime 覆盖。TaskRuns 是唯一 durable queue，手动 WAIT 默认；SKIP/FAIL_FAST 只改变 Workspace 资源等待，不覆盖 Task FORBID/QUEUE/ALLOW。FORBID 同 Task 冲突持久 SKIPPED；定时/Webhook/GitUpdate 固定 WAIT。

DISCOVERED 且 RETIRED 的 Task 对手动与自动 Run 一律 TASK_NOT_READY；脚本重新出现也须显式恢复/reconcile 后重验，不能由普通手动 Run 绕过。普通 disabled MANUAL Task 的手动运行保持当前语义。备份仅在有匹配当前 Workspace/source generation/revision/inventory hash/commit/key/path/reason 的成功 reconciliation proof，且 Task 为 DISCOVERED + RETIRED + disabled 时可记录 RETIRED_MISSING_EXPECTED；该备份诊断绝不构成可执行资格。

WAIT 受绝对 deadline/上限；manual 队列满 429 不建 Run，事件受理持久 SKIPPED 防重复；候选 900 秒、32/Task、128/Workspace、1024/平台需 S1 容量验证。FAIL_FAST admission 时 busy 返回 409/noRun；probe 当时空闲不承诺稍后必运行，第一次真正 acquire 若竞争失败则该已受理 Run 为 SKIPPED/WORKSPACE_BUSY，不回 WAIT。SKIP 同样在第一次真实 acquire 决策。source 变化终态 SKIPPED/SOURCE_SUPERSEDED，无 attempt/no spawn，不自动换源重试。详情轮询返回 200 的 Run 结果不改变曾经 202 受理语义。

## 6. Runtime、ENV、Config、Hook 的请求规则

Runtime 只 Task override→Workspace default；缺 managed 环境为 readiness 失败，无 host fallback。default 按 kind 独立版本，environment_id=null 表示删除该 default（不是 fallback 到 Host）。Workspace 可有多个 Profile，Task 选择同 owner Profile > Workspace default；变量 System allowlist→Global→ 所选 Profile→Task SET/UNSET，**不叠多个 Profile**。

Secret 读取始终 value=null/has_value；System preview 值也 mask。写 SET 时新值必须显式，既有 secret 不带 value 保持；replace_secret=true 才替换，clear=true 才明确清除，二者互斥；UNSET 不能同时携带 value。clone 同 Workspace 但不返回秘密；跨 Workspace 绑定/clone 目标拒绝；Profile 删除有默认/Task 引用则 409。变量名保留当前 ENV_NAME 和 runner-reserved 限制，值是 literal，不插值、不 source shell。

**精确收束**：WorkspaceConfigBinding 只 ATTACH，Task ATTACH/MASK。[TaskConfig.save](../../../back/services/taskConfig.ts#L62)实际明确拒绝 repository scope MASK；旧报告“Workspace ATTACH/MASK”是过宽的目标建议，不能当当前服务行为。MASK 的 asset_id/revision_id 都 null；ATTACH 必须有效 asset，revision_id 可显式固定同 asset revision，null 则在 resolve 时选 current 并把实际 revision pin 入 ExecutionContext/TaskRun，运行中不跟随 asset current 漂移。

Hooks 仍仅 Task 所有；cwd_base TASK_CWD/WORKSPACE_ROOT，phase BEFORE/AFTER_SUCCESS/AFTER_FAILURE/FINALLY，失败策略保留。配置预览只返回挂载/版本/secret 标志，不返回 secret 内容或绝对目标路径。

## 8. 保留域、退出接口及资格边界

保留域的当前请求/响应字段、路径与权限按 JSON 的 retained_domains 所列源码保持，只有 owner/reference/backup 完整性按本合同调整；不借 S0 升级依赖、替换通知协议或重设计认证。旧 Subscription status/pid 直写接口没有 v2 公开替代，Sync 内部状态机唯一写入。旧 Worktree remove-record 没有普通 UI 等价接口；不得删除缺失记录来绕开 TaskSource/历史约束。移除旧 namespace 在 S3/S4 实施且所有有效职责和资格 gate 通过后执行，本轮一个都没删除。

未知 `/api/*` 必须在 SPA fallback 前返回 HTTP404 安全 JSON / API_ROUTE_NOT_FOUND；不能让退役或拼错 API 被 `app.get('*')` 返回 HTML200，也不为旧 Subscription/Worktree 补兼容入口。这是 S4 接线验收要求，本轮未改 Express。

API 授权验收必须覆盖无 token/过期 token/伪造 JWT/有效 App arbitrary workspaces scope/Panel token、/open rewrite、base URL 大小写尾斜杠、Webhook secret 误用、GET 文件/错误分支/JSON parser 错误。覆盖新 GET 并非只测 POST；资源存在性和秘密内容不向未授权者泄漏。并发 CAS/无 overwrite、delete-reclaim 保历史、source superseded、Sync applied-but-discovery-failed、restorepending 与 backup admission 都需端到端验证。

本轮验证等级：现有装配与字段源码复核 **STATICALLY_VALIDATED**；129 条 route 字段齐全、method/path 无重复、全部错误引用属于 74 码 registry 的脚本检查及独立 DTO `tsc --noEmit --strict --skipLibCheck --target ES2022 --module ESNext` 通过，均属 **STATICALLY_VALIDATED**；路线/DTO/错误互相覆盖 **DESIGN_VERIFIED**；本轮没有启动 HTTP/浏览器，API 端到端 **NOT_RUN**。候选 DTO/JSON 是设计工件，不能声称生产路由已部署。实际验收见 [S0_ACCEPTANCE_GATES](S0_ACCEPTANCE_GATES.md)。
