## 1. 实际注册与权限边界

- [主 API 注册器](../../../back/api/index.ts#L19)顺序注册 Backup、User、Runtime、Observability、Task、Config、Log、Open、System、Workspace、GitResources、Subscription 等，最后统一 `protectApiMutations(app)`。`workspaceRoutes()` 内先注册 `codeWorkspaceRoutes()`；`gitResources()` 内注册 scoped ENV；`taskRoutes()` 内注册 Trigger 与 Discovery。因此 Discovery 不在 Subscription 路由模块内，不能仅删除 `back/api/subscription.ts`。
- [Express 装配](../../../back/loaders/express.ts#L39)依次处理大小写保护、base URL、Backup Admission、独立 Webhook、body parsers、JWT、Panel/App token 校验，然后将 `/open/*` rewrite 到 `/api/*`，最终挂载 `routes()`（第 183–184 行）。API 的 `/workspaces/:worktreeId` 当前并非 Workspace 实体：参数直接交给 `CodeWorkspaceService`，指向 Worktree。
- GitResources、Workspace、CodeWorkspace、Tasks、Triggers、Discovery、Scoped ENV、Config、Runtime、Observability 均在各自 wrapper 拒绝 `/open` 来源。Subscription 使用共享 App token scope 验证，没有同样的 Panel wrapper。当前 `back/data/open.ts:27` 的 AppScope 类型并不包含 subscriptions，而前端 scopes 包含它，`back/api/open.ts:29,49` 又允许任意字符串 scopes；这属于现有类型/UI/运行时合同不一致，不能把 TS union 当运行时拒绝证据。新 Workspace、Sync、Discovery、文件写入必须显式采用 Panel-only 策略；不要依赖改名后恰好无法匹配旧 AppScope。
- `/hooks/:publicId` 是 [独立 Webhook](../../../back/api/triggerWebhook.ts#L7)，在全局认证/body parser 前以触发器 Secret、64 KiB 请求上限及 Idempotency-Key 管理；应继续保留独立边界。它只提交 TaskRun，不能变成 Git 同步回调。
- [Tasks 注册](../../../back/api/tasks.ts#L45)还会 `executionService.start()`、`triggerScheduler.start()`；[Runtime 注册](../../../back/api/runtime.ts#L68)启动 recovery；[Observability](../../../back/api/observability.ts#L137)启动通知 dispatcher。下一阶段移除 Subscription scheduler 不能连带停止这些责任。将新 SyncScheduler 的启动/关闭放到明确 lifecycle owner，路由只委托调用，不再扩散注册副作用。

当前没有两个相同的 `DELETE /repositories/:id`：它由 `workspace.ts` 交给 RepositoryStorageService 执行，`gitResources.ts` 只提供元数据读取/保存及测试。目标是把该职责集中回 Repository API 模块，不应根据历史报告误报或删除有效引用保护。

## 5. 正式错误码与并发控制设计

以下为建议冻结的 v2 HTTP 合同；实际数值映射在实现前契约测试确认。当前错误风格混合 `error_code`、`message`、HTTP status 与 body.code，不能声称已一致。

| 场景                                     | HTTP / error_code                                                                  | 并发/客户端要求                                                                                                                        |
| ---------------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace/Task/SyncRun 不存在            | `404 WORKSPACE_NOT_FOUND / TASK_NOT_FOUND / WORKSPACE_SYNC_RUN_NOT_FOUND`          | 不把 Worktree 404 自动回退为 Local                                                                                                     |
| type 不支持 Git/scheduled sync/discovery | `422 WORKSPACE_TYPE_UNSUPPORTED / GIT_REF_POLICY_INVALID`                          | 服务端验证，UI capabilities 仅展示控制                                                                                                 |
| 绝对路径、`..`、受保护路径/链接          | `400 WORKSPACE_PATH_INVALID`；`403 WORKSPACE_PATH_FORBIDDEN`                       | 不回传 root/真实宿主路径                                                                                                               |
| 文件 CAS 失败/目的存在                   | `409 WORKSPACE_FILE_CONFLICT / WORKSPACE_DESTINATION_EXISTS`                       | 保留浏览器草稿；重新读取、比较，由用户保存新版本；不得 blind retry                                                                     |
| 被 TaskSource 引用的入口/父目录删改      | `409 WORKSPACE_FILE_REFERENCED`                                                    | 返回引用；先显式重绑或删除 Task，再操作文件；不修改 TaskSource                                                                         |
| DB 版本或 content revision 过期          | `409 WORKSPACE_VERSION_CONFLICT / TASK_VERSION_CONFLICT / DISCOVERY_PREVIEW_STALE` | expected_version 及 preview token；重读后提交                                                                                          |
| 执行/编辑/同步租约冲突                   | `409 WORKSPACE_BUSY`（带安全 retry_after 与 owner kind）                           | 同一规范化 workspace lock key；无绕过参数                                                                                              |
| Dirty、本地提交领先/分叉/冲突            | `409 GIT_DIRTY / GIT_DIVERGED / GIT_CONFLICT`                                      | 自动同步停止；不 hard reset、stash 或自动覆盖                                                                                          |
| 未恢复配置/节点绑定/恢复待完成           | `409 WORKSPACE_RECOVERY_REQUIRED`；全平台恢复 `503 RESTORE_PENDING`                | 任何读/写/Run 同样 fail closed；由恢复 owner 清理                                                                                      |
| 删除存在 Task/Run/Sync/Journal 引用      | `409 WORKSPACE_REFERENCED / WORKSPACE_BUSY`                                        | 返回脱敏 Task/历史 Run/SyncRun 引用计数/ID；历史 workspace_id RESTRICT，默认 archive/tombstone；无历史且满足保全政策才可显式物理 purge |
| 无 Panel session 或无 WRITE credential   | `401/403 PANEL_SESSION_REQUIRED / GIT_WRITE_REQUIRED`                              | 全新路径与 `/open` rewrite 均覆盖测试                                                                                                  |
| 配额/过大文件/导入预算                   | `413 WORKSPACE_FILE_TOO_LARGE` 或 `422 WORKSPACE_QUOTA_EXCEEDED`                   | 提交前限制+磁盘余量+中途预算；无静默部分成功                                                                                           |

Workspace references 返回至少 tasks_count、historical_runs_count、sync_runs_count、active_operations、recovery_required，以及可供 UI 展示的脱敏 IDs；历史 FK 与执行恢复指针分别计数。Workspace metadata/policy/discovery/runtime defaults/Config/Profile 编辑都需要版本 CAS。文件内容使用现有 expected_hash；删除/目录改名使用 identity 与父目录保护。Workspace 内容每次受控变更递增 `content_revision`；外部脚本写文件时 lease 不能保证它遵守 API，故执行源 fingerprint 与稳定遍历仍需校验，详见安全报告。

## 6. 接口验收清单

1. 空库仅创建 LOCAL → 创建/编辑 `.py/.js/.ts/.sh` → Workspace entries → Task 保存/validate/run → TaskRun/Logs；全流程没有 Repository/credential/subscription 请求或隐藏必填字段。
2. GIT 选择 Branch/Tag/Commit；Branch 手动、Cron、Interval 使用同一个 SyncRun admission；Tag/Commit reject SCHEDULED。`GET refs`/fetch 不更新 Workspace、不创建 TaskRun。
3. 同 repo/ref 两 Workspace 不复用目录、ENV/runtime/config/discovery owner；一个 Workspace 的 edit/sync/lease 不改变另一个目录，Repository fetch 的共享锁仍正确。
4. API/UI 同时保存、目录 rename、Sync 对 Run、Backup 对 edit、恢复对所有 mutation，分别验证 CAS/lease/barrier 和原子结果；未恢复 materialization 时拒绝读取秘密注入文件。
5. 删除 Task 不删代码；删 Workspace 有 Task/历史 Run/SyncRun 引用拒绝并提供 archive；删 Repository 有 GitWorkspace 引用拒绝；取消 SyncRun 不取消 TaskRun；相同 commit 重试无重复 GitUpdate Run。
6. 所有新/改路由在 Panel、无 token、过期 token、App token、`/open` rewrite、base URL、大小写/尾斜杠等边界验证；结构化错误不含 Secret/宿主路径/SQL 原文。
7. Snapshot 中含 Local 唯一脚本与 source/profile/default/binding 关系；恢复后 entries/read/validate/run 可用；缺失代码恢复不得返回 ready。

这些是后续实施 Gate，本轮仅静态审查，结果均为 **UNVERIFIED**。
