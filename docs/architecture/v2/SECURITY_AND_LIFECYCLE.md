# ZhiXu 2.0 — 安全、资源生命周期与失败契约

状态：架构设计评审，未实施。产品约束见 [TARGET_ARCHITECTURE](TARGET_ARCHITECTURE.md)，执行/备份证据见 [EXECUTION_AND_BACKUP](EXECUTION_AND_BACKUP.md)，同步恢复见 [SUBSCRIPTION_SYNC_DESIGN](SUBSCRIPTION_SYNC_DESIGN.md)，阶段顺序见 [IMPLEMENTATION_ROADMAP](IMPLEMENTATION_ROADMAP.md)。本报告的风险级别是设计评估；不得与 GitNexus 图风险、历史测试 PASS 混为一谈。

## 1. 保护边界与高风险结论

新增 LOCAL 使脚本源码可能只存在平台内；数据丢失风险为 **CRITICAL**。TaskSource、lease identity、Config journal、恢复路径、Backup domain、Git 同步 owner 的切换属于 **HIGH** 跨域变更。只改 `worktree_id` 字段、只迁 Cron、只开放编辑器中的 LOCAL 选项都不能满足安全契约。

现有路径和锁机制有可复用价值，但当前没有 LOCAL Workspace 身份，也没有它的生命周期/完整性测试。以下矩阵将“当前保护”与“目标保护”分开；目标保护全部需下一阶段编码与资格验证，本轮不宣称通过。

平台当前执行可信用户提供的脚本；managed Runtime 隔离的是解释器/依赖/环境，不是租户级 OS sandbox。workspace advisory lock 约束合作服务和受监督子进程；同 UID 的任意外部进程/脚本主动改写文件不由锁自动阻止。对不可信脚本的容器/用户/只读根隔离是额外技术范围，现状为 **UNVERIFIED**。

## 3. Workspace 生命周期和文件资产

建议持久 lifecycle state：`CREATING → READY → DELETING → DELETED`，异常 `ERROR/RECOVERY_REQUIRED`；显式归档为 `READY → ARCHIVED`，拒新执行/同步/文件写入，保留经授权且持 lease 的安全文件读取、元数据和历史诊断。恢复使用单独显式 unarchive 操作，重验 root/恢复 journal/source/readiness 后才回 READY，不自动重新启用曾关闭的 Task/Sync policy。需要修复缺失资产时用明确诊断 `SOURCE_MISSING`，不可通过 mkdir 空 root 自愈为 READY。Git 同步状态放在 Git 扩展/SyncRun，与 Workspace 生命周期分开，避免把一次网络失败等价成 Workspace 不可编辑。

创建 LOCAL：平台 admission→ 分配 Workspace ID 与 CREATING 记录 → 派生系统目录 →owner marker（version/id/type/dev/ino）→ 安全目录初始化 →READY。失败重启只处理可证明 owner 的 staging/root；未知文件保留并告警，不能递归清空。CREATE 完成与 API 成功需在目录 fsync/元数据可恢复后发生。Git 同样先建 owner，再由 Git adapter 创建私有本地 branch 与 worktree；失败后谨慎回收该 Workspace 专属资源。

Workspace 类型、Repository 和 ref 不作为普通 PATCH 可随意改动字段。调整内容来源应创建新的 Workspace 并显式重新绑定 Task，或后续设计独立的受审来源变更流程。此限制保护 Task 语义，与“Branch 可同步到新 commit”不冲突。

文件 remove/rename 前应显示受影响 Task 引用；推荐首期阻止删除/改名被活跃 TaskSource 引用的入口或其父目录，用户先显式修改/删除 Task。普通被 import 的辅助文件无法靠入口引用图完全确定，文件变更必须使 Workspace source version 推进，readiness 标记需要重新检查。不能声称静态引用计数能证明所有脚本运行时依赖。

删除 Workspace：在 admission/Workspace EX lease 内检查并复查引用与 journal；若 TaskSource、活动资源或历史 RESTRICT 引用存在，返回 409 且保持原 lifecycle，不因失败请求留下 DELETING 或永久关闭调度。单独 archive 通过显式操作阻新运行并保留任务/代码；只有引用、保全和恢复条件全部满足的 purge 才关闭新 admission→DELETING→ 可验证 owner 的目录移至受控隔离区 →DB 最终状态。是否提供用户回收站/保留期限是待审产品技术参数；任何实现都不得因 fresh-only 自动删 Task、Run 历史或唯一源码。完整 Backup 在删除期间不能取到半状态。

## 4. 锁、版本和恢复契约

统一锁序见 [执行专项](EXECUTION_AND_BACKUP.md#3-lease编辑和并发)。所有路径下的同一 Workspace 必须命中同一个 lock inode。OS 锁、DB 版本、幂等 key 负责不同维度：锁保护文件操作并发，version 拒绝过期写入，idempotency 防止请求重试重复副作用。

| 操作                     | 并发控制                                                                      | 失败恢复                                                                          |
| ------------------------ | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 元数据 PATCH/Sync Policy | Workspace version 条件写；schedule generation 随版本更新                      | 旧 schedule callback 带旧 version 即忽略，重启重建一个有效 job                    |
| Save/Delete/Rename       | Workspace EX + expected file hash/identity + atomic fs publication            | 保留编辑 buffer；未知 inode 不覆盖；owned rollback/journal 保留供恢复             |
| Run                      | run owner claim + Workspace EX + runtime/build 共享 pin +定义重读             | supervisor 持 FD，清理后 terminal；不能清理则 RECOVERY_REQUIRED                   |
| Sync                     | Repository lock→Workspace EX、active SyncRun 唯一 claim                       | 以 before/afterHEAD 与 phase checkpoint 识别已更新未完成；重复恢复不重复事件      |
| Discovery/GitUpdate      | 在成功 sync 链中确定 commit；DB transaction + workspace ownership +eventdedup | 失败保留 pending checkpoint；同 commit 重复不重复触发，失败 sync 无 success event |
| Backup                   | barrier QUIESCING→drain→mutation EX→ 复查 idle                                | 不完整 snapshot 不 READY；恢复 abandoned marker 先证明无 activeowner              |
| Restore                  | backend lifetime EX + RESTORE_PENDING + whole DATA_DIR candidate              | inode/hash journal 状态推进、最终 source 校验、失败 rollback 整根                 |

错误码建议归属：400 `WORKSPACE_PATH_INVALID/WORKSPACE_TYPE_INVALID`；403 鉴权/capability 与 reserved 路径；404 不存在资源；409 `WORKSPACE_BUSY/WORKSPACE_FILE_CONFLICT/WORKSPACE_VERSION_CONFLICT/WORKSPACE_REFERENCED/GIT_DIRTY/GIT_DIVERGED/WORKSPACE_RECOVERY_REQUIRED`；503 `PLATFORM_BACKUP_IN_PROGRESS/RESTORE_PENDING`。错误响应可含 safe code、operation/workspace ID、retryable、current_version；不得含 secret、host 绝对路径或原始 Git stderr。保持现有 API 统一 envelope，具体 HTTP 契约与 API 清单一并冻结。

## 5. LOCAL 首期边界与增强功能成本

首期必须交付网页创建 Workspace、目录/文本文件创建、打开/编辑/保存、rename/delete、文件名/内容 search、Task 绑定及执行；不需要 Git 初始化、Credential、Repository 或 Subscription。文件扩展名不等于文件类型：编辑仅 UTF-8 文本与当前支持脚本，binary 可按现有只读限制；FIFO/socket/device/symlink/hardlink 一律拒绝。大小、路径深度、文件数、search 扫描上限与 deadline 按安全参数统一，而不是前端单独限制。

| 增强功能          | 实施成本（相对基础文本编辑）                                                                      | 必需边界                                                                                                        | 首期依赖                              |
| ----------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| 单文件上传        | 中：multipart streaming、staging、限额、进度、overwrite 策略、鉴权与 UI                           | 服务端实际字节计数，禁止 client 路径、no-follow，scan/类型校验，不覆盖过期 hash；在同 lease 内原子 publish      | 可后置；不影响首期 create/edit        |
| ZIP 导入          | 高：档案审计、目录冲突计划、展开流量配额、文件数/深度/ratio、事务式发布、取消恢复、浏览器错误流程 | 只解到 owned staging；拒绝路径逃逸/links/special/重复冲突/嵌套 bomb；原子 tree publish；backup 验证新 tree 完整 | 必须独立阶段，不能成为首次 LOCAL 必需 |

上述成本是工作量等级，不是工期承诺；精确人日和可用安全扫描能力为 **UNVERIFIED**。Upload/ZIP 的策略参数只属于待审技术细节，不将 LOCAL 本身或 Subscription 移除重新列为 open decision。

## 6. 必须重新资格验证的失败集合

当前历史 Phase12/14/15/16 证据仅用于找到可复用测试工具，不能证明 v2。除功能 happy path 外，完整资格必须包含：

- Workspace/source/path/schema/manifest 契约、约束/FK/delete restrictions、clone/manual/discovered 归属和 fresh 数据库失败恢复。
- 用户源安全路径、symlink/hardlink/special 文件、race 与异步 barrierFD；preserved 文件 hash、mode 和 inode 归属证据。
- Run/Config/Node binding/Sync/Discovery/GitUpdate/Restore 关键点 SIGKILL 和重启，区分可重试 BUSY 与须人工修复 RECOVERY_REQUIRED。
- LOCAL 无 Git 完整流程、同 repo/ref 多个独立 GitWorkspace、固定 Tag/Commit、dirty/local divergence、privatebranch/Push 映射。
