# S0 Error Code Contract

状态：**TECHNICAL_CONTRACT_READY_FOR_APPROVAL**。唯一机器注册表为 [error-codes.json](contracts/error-codes.json)，API 使用位置见 [api-contracts.json](contracts/api-contracts.json)。本轮没有改动当前错误处理器或生产 locale。

## 1. 错误响应与安全边界

新资源沿用`code/data` envelope；失败 HTTP status 与 body.code 一致，附`error_code`、固定安全 message、retryable、脱敏 resource/operation 及有限 details。不得传播 Token、私钥、Secret ENV、absolute host path、原始 Git stderr、SQL 错误或 request body 片段。所有未知内部异常使用 WORKSPACE_OPERATION_FAILED；原始原因只写受控脱敏诊断。

`retryable=true`表示操作可在条件变化后按说明重试，不表示客户端可盲重投或 terminal Run 自动 retry。CAS 冲突必须重读；幂等重放用原 key 取结果；有意新 Run 才用新 key。`SOURCE_SUPERSEDED`和等待/策略 SKIPPED 是 Run 结果码：已受理操作仍通过 HTTP200/202 查询，不能把表中 409 误套为异步结果的传输状态。终态 SKIPPED 没有 attempt、没有 script exit code，不能变为 FAILED 冒充脚本失败。

下表 HTTP 是**直接请求拒绝**的映射；Resource/Operation 是错误所属域，不包含绝对路径。message 是协议安全 fallback，UI 用 error_code 作 i18n 翻译；不能把内部 enum 或异常文本原样拼接。

## 3. 现有码到新边界的单向映射

这些是将 Git 内部 adapter 错误转成新 Workspace 边界错误，**不是**同时提供两套同义公开码，也不保留旧 API：

| 当前代码/事实                                                                    | v2 公开合同                                                 | 原因                                                                                                                       |
| -------------------------------------------------------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| WORKTREE_DIRTY / WORKTREE_DIVERGED / WORKTREE_LOCAL_COMMITS / WORKTREE_CONFLICT  | GIT_DIRTY / GIT_DIVERGED / GIT_LOCAL_COMMITS / GIT_CONFLICT | Git 约束归真实 GIT Workspace；旧 Worktree 业务 namespace 退出；[源码](../../../back/services/worktree.ts#L350)             |
| WORKTREE_BUSY / CONFIG_WORKSPACE_BUSY                                            | WORKSPACE_BUSY                                              | 统一同 Workspace 租约，不把 Config 层暴露成另一把锁                                                                        |
| PATH_CONFLICT                                                                    | WORKSPACE_PATH_INVALID 或 WORKSPACE_RECOVERY_REQUIRED       | 参数不安全与已持久 root 身份不匹配分开；禁止带真实路径                                                                     |
| TASK_PROFILE_REPOSITORY_MISMATCH / ENV_PROFILE_REPOSITORY_MISMATCH               | ENV_PROFILE_WORKSPACE_MISMATCH                              | 新运行配置 owner 为 Workspace；[旧 Task resolver](../../../back/services/taskResourceResolver.ts#L339)                     |
| ENV_PANEL_SESSION_REQUIRED / CONFIG_PANEL_SESSION_REQUIRED / PANEL_AUTH_REQUIRED | PANEL_SESSION_REQUIRED                                      | 新受保护管理 API 使用同一显式 Panel principal 规则，不按业务名复制授权码                                                   |
| credentials_required / invalid_token                                             | AUTHENTICATION_REQUIRED，HTTP401                            | 新 namespace 安全包装；保留旧认证协议不要求改其全局 response                                                               |
| TASK_CONCURRENCY_FORBID                                                          | 原码保留                                                    | 当前 ExecutionService 确有此 skipCode；不能新增同义 FORBID 错误，见[源码](../../../back/services/executionService.ts#L133) |
| CONFIG_EDIT_CONFLICT / ENV_NAME_INVALID / ENV_VALUE_INVALID                      | 原码保留                                                    | 已有子域校验，区别于 Workspace metadata 版本冲突；不做全局字符串替换                                                       |
| BACKUP_RECOVERY_REQUIRED / PLATFORM_BACKUP_IN_PROGRESS                           | 原码保留                                                    | 既有备份恢复责任，不因新模型改名移除                                                                                       |

当前通用 Express handler 可能返回 Sequelize 原始错误；S1/S4 新 namespace 必须在此之前净化，不能把原 SQL 异常当 safe message。该要求是目标改造契约，不声称现在所有 API 都统一。

## 4. 版本、状态与动作一致性

- WORKSPACE_TYPE_INVALID 用于合法请求形状但类型/操作组合不支持；非法 JSON/未知字段用 INVALID_REQUEST，避免同义重复。
- WORKSPACE_NOT_READY 用于 CREATING/ARCHIVED/TOMBSTONED/存储已回收等不允许该操作的生命周期；有未恢复 journal 明确 WORKSPACE_RECOVERY_REQUIRED；新 Sync 遇该域未完成为 SYNC_RECOVERY_REQUIRED。
- GIT_LOCAL_COMMITS 不归入 DIVERGED：ahead-only 也阻自动同步，避免用单一 dirty/failed 掩盖本地提交。
- WORKSPACE_REFERENCED 的 live Task/active 资源阻 source 删除；历史引用仅阻 metadata purge。错误 details 分别返回 physical_reclaim_blockers 和 metadata_purge_blockers 的安全计数，不能把 history_count>0 当磁盘永久锁定。
- WORKSPACE_BUSY 可能是直接 409，也可能是已接受 SKIP/FAIL_FAST Run 终态的 error_code；同码所属资源动作可辨识，HTTP 层不决定 TaskRun 状态。
- backup quiesce 拒绝新写/新 producer；稳定 QUEUED Run/Sync 与未 claim outbox 可被快照保留，deadline 不延期。RESTORE_PENDING 只放行明确安全 status/diagnostic，不放行 Files GET 读取未知 source。
- 所有 Registry 值和 source mapping 仅经静态/设计检查；生产错误响应、locale、auth 和并发行为 **NOT_RUN**，不得称 API 验证 PASS。
